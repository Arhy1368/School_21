## Вопрос 1. Какие баги были выявлены: количество, описание, почему SonarQube их считает багами?

**Ответ:** Было выявлено **2 бага** (Bugs).

| № | Описание | Причина (Why is this an issue?) |
|---|----------|--------------------------------|
| 1 | **"Either re-interrupt this method or rethrow the InterruptedException"** (строка 48) | SonarQube считает это багом, потому что `InterruptedException` не обрабатывается должным образом. Если метод прерывается, поток должен корректно завершить работу. Игнорирование этого исключения может привести к проблемам с многопоточностью и непредсказуемому поведению программы. |
| 2 | **"Introduce a new variable instead of reusing the parameter 'clean'"** (строка 58) | SonarQube считает это багом, потому что изменение входного параметра метода является плохой практикой. Это может привести к путанице при чтении кода и скрытым ошибкам, так как параметр не ожидает изменения. Лучше создать новую локальную переменную. |

## Вопрос 2. Какие уязвимости были выявлены: количество, категории, описание, почему SonarQube их считает уязвимостями?

**Ответ:** Было выявлено **1 уязвимость** (Vulnerability).

| № | Категория | Описание | Причина (Why is this an issue?) |
|---|-----------|----------|--------------------------------|
| 1 | **Security** (CWE) | **"Add password protection to this database"** (строка 54) | SonarQube считает это уязвимостью, потому что база данных H2 запускается без пароля. Это означает, что любой, кто имеет доступ к сети, может подключиться к базе данных без аутентификации. Это критическая проблема безопасности, так как злоумышленник может получить доступ к данным или изменить их. |

---

## Вопрос 3. Какие Security Hotspots были выявлены: количество, категории, приоритет, описание, почему SonarQube их считает Security HotSpot'ами?

**Ответ:** В веб-интерфейсе SonarQube был выявлен **1 Security Hotspot** (в CSV он не попал, так как это отдельный тип проблемы).

| № | Категория | Приоритет | Описание | Причина (Security Hotspot) |
|---|-----------|-----------|----------|---------------------------|
| 1 | **Authentication** | Medium | Использование базовой аутентификации (Basic Authentication) | SonarQube считает это Security Hotspot'ом, потому что базовая аутентификация передаёт пароль в открытом виде (base64). Это требует ручного анализа для проверки использования HTTPS и оценки риска. В отличие от уязвимости, это не точно проблема, а место, которое нужно проверить разработчику. |

## Вопрос 4. К каким CWE идёт отсылка для Security Hotspots?

**Ответ:** Для Security Hotspot'ов (и уязвимостей) указаны следующие CWE:

| Проблема | CWE | Описание CWE |
|----------|-----|--------------|
| Security Hotspot (Basic Authentication) | **CWE-522** | Insufficiently Protected Credentials (Недостаточно защищённые учётные данные) |
| Vulnerability (База данных без пароля) | **CWE-522** | Insufficiently Protected Credentials (Недостаточно защищённые учётные данные) |
| Vulnerability (База данных без пароля) | **CWE-284** | Improper Access Control (Неправильный контроль доступа) |

**Источник:** Вкладка `How can you fix it?` в SonarQube для каждой проблемы показывает соответствующие CWE.

## Вопрос 5. Какие запахи кода были выявлены: количество, описание, почему SonarQube их считает запахами кода?

**Ответ:** Было выявлено **6 Code Smells** (запахов кода).

| № | Описание | Причина (Why is this an issue?) |
|---|----------|--------------------------------|
| 1 | **"Remove this unused import 'java.io.IOException'"** (строка 10) | Неиспользуемые импорты загромождают код, увеличивают время компиляции и создают лишние зависимости. Это усложняет поддержку кода. |
| 2 | **"Replace this use of System.out by a logger"** (строка 32) | Использование `System.out.println` для логирования не даёт возможности настраивать уровни логирования, управлять выводом в файл и ротацией логов. Лучше использовать специализированные библиотеки (например, Log4j или SLF4J). |
| 3 | **"Remove this expression which always evaluates to 'true'"** (строка 62) | Условие всегда истинно, поэтому проверка бессмысленна. Это усложняет чтение кода и может быть признаком ошибки. |
| 4 | **"Define and throw a dedicated exception instead of using a generic one"** (строка 68) | Использование общих исключений (`Exception`) не даёт информации о характере ошибки. Специализированные исключения делают код более понятным и облегчают обработку ошибок. |
| 5 | **"Define and throw a dedicated exception instead of using a generic one"** (строка 92) | Та же проблема, что и в пункте 4. Повторяющийся код-запах. |
| 6 | **"Don't use the query 'SELECT *'"** (строка 76) | Использование `SELECT *` в SQL-запросах снижает производительность, так как извлекаются все колонки, даже если нужны только некоторые. Также это ухудшает читаемость и усложняет сопровождение. |
